# Native x86 Rust-facade companion

`x86_64_runner.py` is the native Linux/x86-64 companion for Rust-facade
measurements. It is separate from the preserved AArch64-only
`run.py`: it never invokes that runner, does not use its `/tmp` workspace, and
does not change its three existing route bodies.

This companion is test infrastructure. It constructs ordinary stock-std
`x86_64-unknown-linux-musl` benchmark executables inside the pinned native
image. It is neither an owned crabc runtime/product proof nor a musl C-ABI
oracle. It does not use `-Z build-std`, a replacement standard library, an
unwinder provider, or an allocator qualification path.

## Fixed workload and admission

The profile has five source-bound rows, in this exact Rustybench output order:

| Row | Source | Observable operation |
| --- | --- | --- |
| `native_x86::caller_buffer` | x86 supplement | `readlinkat_raw` reads a private fixed symlink into a caller-owned `MaybeUninit` buffer and proves its unused suffix remains intact. |
| `native_x86::missing_error` | x86 supplement | `open` of a private absent path must return `ENOENT`. |
| `native_x86::frozen::clock_gettime` | frozen source | Existing `CLOCK_MONOTONIC` route. |
| `native_x86::frozen::getpid` | frozen source | Existing `getpid` route. |
| `native_x86::frozen::open_close` | frozen source | Existing `/dev/null` open/close route. |

`x86_64_fixture.rs` nests the checked-in frozen `src/main.rs` by its physical
path. The profile pins that source and its legacy manifest; the runner verifies
those bytes before and after every bounded execution. The separate supplement
adds only the two rows above.

Both modes build each backend once, run its correctness discovery, and then
run the timed Rustybench invocations in alternating backend order. `--mode
full` is the normal contract: five invocations per backend, 100 samples per
invocation, and 1,000 iterations per sample. It is admitted only by the same
reader as the C scorecard: every ordered qualification gate before
`performance.release` must be complete in
`compat/x86_64/qualification_manifest.json`. Until then the dispatcher's
host-side `--full-admission` query refuses it before Docker setup and names
each open gate; the containerized runner and the report reader check it again,
and a report records, never asserts, that result. `--mode smoke` is always
available: one invocation per backend, two samples, and three iterations per
sample. It is an implementation check, never a performance score or promotion
result. This companion is a supporting comparison with no release threshold of
its own.

## Inputs, lock, and build boundary

The runner requires two immutable physical Git inputs:

- Rustybench commit `de81e89e2eb2c05b820144412d82a260e7d28cdb`, version
  `0.1.0`. Its canonical clone is
  `https://github.com/laputa-systems/rustybench`; its frozen `Cargo.toml`
  retains the earlier `https://github.com/joshuarli/rustybench` repository
  spelling. Both identities are retained rather than rewritten.
- Rustix commit `cf67411d572468d5fc39e8ac8b4e649ae3e5e9ec`, version `1.1.4`,
  from `https://github.com/bytecodealliance/rustix`.

`x86_64_profile.toml` pins each revision, Git tree records, required source
files, the frozen fixture/manifest/supplement/lock hashes, the repository
Cargo configuration consumed from the workspace ancestry, and the exact image
identity. `x86_64_Cargo.lock` retains every registry checksum. A preparation
step may fetch that static lock into a private `.work/x86_64` Cargo home; the
smoke uses the prepared cache with Cargo offline and no Docker network.

Rustybench's normal active x86 graph is exactly the profile's
`active_crabc`/`active_rustix` roster. Both routes include `rustybench`, its
local `rustybench-macros` proc macro, `regex-lite`, `lexopt`, `miniserde`, and
their locked registry closure (`itoa`, `mini-internal`, `proc-macro2`, `quote`,
`syn`, `unicode-ident`, and `zmij`). The crabc route adds `crabc-rs`,
`crabc-core`, and `bitflags`; the Rustix route adds `rustix`, `bitflags`,
`errno`, `libc`, and `linux-raw-sys`. The target-filtered metadata roster is
replayed exactly, so an omitted, added, or substituted active package fails.
The reader binds each `dependency_graph.metadata` file to its retained Cargo
metadata-command stdout, rebuilds the active node ids, package/source records,
and exact activated-feature roster from that raw response, then maps its fixed
Docker execution paths back to independently supplied host roots before
rehashing the trees. The static lock can retain target-inactive Windows
packages, but they are not in either native x86 resolved graph. Rustybench
default features are empty and its optional `quanta-timer` route is forbidden.

The rendered harness has its own workspace and an explicit bench profile:
`opt-level = 3`, fat LTO, one codegen unit, and stripping. It builds with the
image's normal stock musl standard library and no `-Z` option. `crabc-rs` is
selected with default features off; Rustix uses its explicit `std`, `fs`,
`process`, and `time` test facade features. Rustybench itself is standard
library test infrastructure. The frozen source's `AllocProfiler::system()` is
Rustybench allocation instrumentation, not a crabc allocator/provider claim.
The sealed executable is checked as an x86-64 static PIE with no `DT_NEEDED`.

## Invocation and retained evidence

Use the pinned dispatcher from the checkout. The two immutable source inputs
and every report path are physical paths below this checkout's `.work/x86_64`
boundary:

```sh
RUSTYBENCH="$PWD/.work/x86_64/native-facade-inputs/rustybench"
RUSTIX="$PWD/.work/x86_64/native-facade-inputs/rustix"
REPORT="$PWD/.work/x86_64/native-facade-smoke.json"

./scripts/dev-x86_64.sh perf-native --prepare \
  --rustybench-source "$RUSTYBENCH" --rustix-source "$RUSTIX"

./scripts/dev-x86_64.sh perf-native --mode smoke --report "$REPORT" \
  --rustybench-source "$RUSTYBENCH" --rustix-source "$RUSTIX"

./scripts/dev-x86_64.sh perf-native --validate-report "$REPORT" \
  --rustybench-source "$RUSTYBENCH" --rustix-source "$RUSTIX"
```

The full comparison uses the same commands with `--mode full` and a fresh
report path; `./scripts/dev-x86_64.sh perf-native --mode full` alone prints
the current admission and its open gates.

The dispatcher supplies the runner's read-only `/inputs/rustybench` and
`/inputs/rustix` mounts, a fixed `/workspace` execution namespace, and an
image-derived `CRABC_PERF_X86_IMAGE_ID`. Preparation alone has network access;
the smoke runs with `--network none`. Host replay maps retained execution
locations to the supplied host sources without rewriting the report paths.

Each backend retains its Cargo build/metadata command, target-filtered package
graph, compiler/tool identity, ELF/readelf bytes, exact artifact hash, raw
`--test` discovery tree, raw `--bench --format json` stdout/stderr, process
PID/affinity status, CPU/frequency diagnostics, and source snapshots before
and after. Direct artifact execution includes `--bench` explicitly because
Cargo would otherwise supply that selector; without it Rustybench defaults a
direct artifact to its test action and emits no timed JSON. The raw JSON must
contain all five rows in order, exact smoke geometry, and all supported CPU,
fault, context-switch, RSS, and PSS fields. Missing resource values are never
converted to zero. The host reader rehashes all retained evidence and
recomputes the derived totals from raw data. It also replays the exact pinned
Rust release, commit hash, host triple, Cargo version, and installed-target
roster from their retained raw tool outputs; a matching executable pathname
alone is insufficient.
