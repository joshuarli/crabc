# Native Linux/x86-64 runtime parity goal

## Status and scope

This is the active plan for bringing `crabc`, `crabc-libc`, `crabc-ldso`, the
CRT/sysroot, and `crabc-rs` to the same selected capability boundary as the
current Linux/AArch64 runtime.

It authorizes native Linux/x86-64 little-endian work only, with Linux 5.10 as
the kernel baseline. It does not authorize AArch64 emulation, another
architecture, a portability framework, or public x86-64 support. Until every
promotion gate below passes, Linux/AArch64 little-endian remains the only
supported public platform.

This document is deliberately a forward-looking goal and handoff. The exact
completed evidence belongs in
[`compat/x86_64/parity.toml`](compat/x86_64/parity.toml) and
[`compat/x86_64/README.md`](compat/x86_64/README.md), not in a growing list of
historical one-command checkpoints.

## What parity means

Parity is semantic coverage of the selected AArch64 runtime profile, not a
symbol count or a mechanical C-wrapper count. Each selected capability needs
an x86-64-native implementation, any required target ABI/layout proof, and
repeatable native evidence.

The completed target includes all of the following:

- `crabc-core`: x86 syscall, ELF/vDSO, TLS/thread-pointer, atomics/futexes,
  signal-frame, floating-point, and typed kernel-record foundations.
- `crabc-rs`: the same useful native runtime capability accounting as AArch64,
  exposed as an idiomatic Rust layer rather than a C ABI mirror.
- `crabc-libc`: the selected C/POSIX runtime, headers/layouts, errno/TLS,
  pthread/TLS, filesystem/process/signal/time/socket/resolver behavior, and
  text/locale/math/stdio profile.
- `crabc-ldso`, CRT, builtins, and an owned sysroot: native static and dynamic
  startup, dynamic loading, TLS, linking, and source-build behavior.
- Native qualification: ABI and behavioral differentials, OS/libc/pthread/
  resolver/loader gates, Rust-std/LTO consumers, source builds, capability
  accounting, and required performance evidence.

The retained profile remains the one in [`SCOPE.md`](SCOPE.md) and
[`COMPATIBILITY-PROFILE.md`](COMPATIBILITY-PROFILE.md): musl 1.2.6 is the C
and POSIX oracle; Rustix is test-only; glibc is never an oracle or fallback;
the resolver is bounded to conventional system files and A/AAAA/CNAME over
UDP/TCP; and there is no NSS, DoH/DoT, mDNS, IDNA policy, general locale
database, or hand-written cryptography.

Fixed mimalloc port work and evidence expansion are paused. Its retained
native x86 evidence is private allocator provenance, not progress toward this
runtime target.

## Current starting point

The parity ledger records a verified native foundation: pinned-musl oracle
provenance, x86 architecture primitives, a broad but bounded direct
`crabc-rs` subset, selected source-only C runtime leaves plus thirty private
static C archive boundaries, checked relative loader/image work, and a static-PIE
CRT foundation with a private first-thread Variant-II TLS bootstrap. That
bootstrap proves only one main-executable local-exec image before static-PIE
lifecycle hooks; it does not select pthreads, dynamic TLS, ldso TLS, an owned
sysroot, or public support. The direct facade now also
includes a complete socket/address transport family: socket lifecycle,
IPv4/IPv6 UDP, IPv4 TCP, typed options, `SIOCATMARK`, and vectored/batched
messages. Its first record-owning network vertical slice also has native x86
evidence: explicit-socket interface index/name ioctls, allocation-free link
enumeration, and owned link/address snapshots from fixed rtnetlink records. A
second private core slice proves caller-owned DNS UDP/TCP exchange behavior.
A third private facade slice selects the alloc-backed resolver and owned hosts
snapshot. A fourth private facade slice selects the owned services and
protocols snapshots, completing the three conventional netdb files. A fifth
private facade slice completes the selected filesystem path-core boundary:
typed descriptor-relative metadata and pathname lifecycle operations, links
and rename, bounded timestamp mutation, and caller-buffered plus owned
byte-preserving symbolic-link target reads. A sixth private facade slice
selects the direct `filesystem.xattr` family: caller-buffered binary values and
NUL-separated name lists through path, no-follow-path, and descriptor forms. A
seventh private facade slice selects allocation-free `filesystem.directory`
records: caller-buffered `getdents64` parsing, owned streams, and opaque
seek/rewind cookies. An eighth private facade slice selects the complete
`filesystem.temporary-objects` family: retained-parent named-file cleanup,
anonymous `O_TMPFILE` descriptors, and private temporary-directory creation.
A ninth private facade slice selects `filesystem.extended-metadata`: direct
`statx=332` into a private Linux 5.10 256-byte record, including a statx-specific
`AT_EMPTY_PATH` form while preserving direct `ENOSYS` behavior. A tenth private
facade slice selects `filesystem.canonicalize` and
`filesystem.cwd-mutation`: bounded byte-preserving physical pathname resolution
and explicitly process-global `chdir`/`fchdir` state transitions. An eleventh
private facade slice selects `process.root-change`: safe
`process::chroot<P: PathArg>` byte paths use direct `chroot=161` and return
direct `Errno`; success changes future absolute pathname resolution
process-wide, leaves CWD unchanged, and offers neither restoration nor a route
to the old root. It is not a containment boundary. A twelfth private facade
slice selects `ipc` POSIX named-message queues: typed direct queue
operations, owned descriptor lifetime, queue attributes, bounded priorities,
absolute realtime deadlines, and unlink-after-open behavior. A thirteenth private
facade slice selects `ipc.posix-shm`: validated POSIX names map directly to
`/dev/shm`, open descriptors are owned and close-on-exec, and unlink-after-open
lifetime remains visible. Its Rust boundary deliberately forces only `CLOEXEC`
to match existing AArch64/Rustix behavior: the default final symlink follows,
while caller-supplied `O_NOFOLLOW` sees direct `ELOOP`. Musl's C wrapper adds
`O_NOFOLLOW` and `O_NONBLOCK` as a recorded intentional difference. A fourteenth private
facade slice selects bounded `system.inotify`: an owned descriptor,
descriptor-scoped typed watches, and caller-buffered byte-preserving events.
A fifteenth private facade slice selects `time.civil-calendar`: direct
wall-clock observation, strict UTC calendar values, immutable explicit
POSIX-TZ/TZif rules, and one-way local-calendar projection. A sixteenth
private facade slice selects `time.clock-query`,
`time.clock-process-id`, `time.clock-set`, and `time.posix-timers`: closed
named clock values, validated process/descriptor clock queries, direct
permission-governed clock mutation, and owned POSIX timers without
`SIGEV_THREAD` callbacks. Wider IPC/system facilities, watcher policy, and the
remaining clock/timer families remain planned. A seventeenth private facade slice
selects `process.child-ownership`: alloc-backed `PreparedExec` preparation,
bounded `FdAction`/`SpawnOptions` child setup, a `CLOEXEC` error-pipe spawn
protocol, and unique consuming `Child` wait ownership through `WaitOptions` and
`WaitStatus`. It remains private Rust-only evidence; the separately selected
static C child-reaping artifact does not turn this into generic Rust child
ownership or supervision. Generic fork/exec, C ABI/TLS/pthread/atfork, and
child supervision remain planned. An
eighteenth private facade slice selects `process.thread-kill`:
`signal::kill_thread` takes typed `Pid` and `Signal` values, fixes the target
thread group to the calling process, and uses direct `tgkill=234` to deliver to
one named thread. It retains direct `ESRCH` and `EINVAL` errors rather than
becoming generic process signaling, a signal-mask/queue/signalfd surface, or a
pthread/C ABI/cancellation facility. A nineteenth private facade slice selects
`memory.mapping`: unsafe `mm::{mmap, mmap_anonymous, mprotect, munmap}` use
closed Linux mapping/protection flags and direct `mmap=9`, `mprotect=10`, and
`munmap=11` seams. The caller retains pointer-provenance and mapping-lifetime
responsibility; this does not select remapping, locking, synchronization,
advice, residency, or VM policy. A twentieth private facade slice selects
`users.databases`: immutable owned strict-UTF-8 `/etc/passwd` and `/etc/group`
snapshots retain source order and duplicates, with first-match name/ID lookup
and whole-snapshot malformed-record rejection. Its direct system loaders cap
each independently read file and do not imply an atomic cross-file account

runtime boundary. A twenty-first private facade slice selects `mount.basic`:

safe `pty::{openpt, grantpt, unlockpt}` allocation steps and `PtyPair::open`

expose only caller-buffered or owned devpts naming. The selected `TIOCGPTN`,
`TIOCSPTLCK`, and internal peer-open lifecycle leaves controlling-terminal and
session transitions unselected from that safe construction step. A
twenty-fourth private facade slice completes the associated typed terminal
vertical: explicit unsafe `PtyPair` session/controlling-terminal handoff plus
private x86 36-byte kernel-termios conversion, named attribute/queue/exclusive
and TTY-path operations. It exposes neither a C termios record nor a generic
ioctl or process-supervisor API.

## Parallel work lanes

To keep throughput high without erasing dependency boundaries, work may fan
out along these lanes:

- **Facade lane:** `facade.record-owning` is foundation-verified by the closed
  aggregate of its private slices. Keep that surface closed while the C-runtime
  artifact chain advances; reopen it only for a deliberate profile change.
- **C-runtime lane:** header/layout closure and errno/TLS integration, then
  selected C/POSIX and pthread/TLS behavior. It may proceed alongside facade
  work but must converge before the ABI-compatibility gate.
- **Runtime-artifact lane:** loader image/relocation and static-PIE foundations
  are already available; dynamic loader/CRT/sysroot work begins once its C
  header, TLS, and ABI prerequisites are real artifacts rather than leaves.
- **Qualification lane:** extend deterministic x86 harnesses as each block
  lands. Full C/POSIX, corpus, Rust-std, source-build, accounting, and
  performance promotion waits for the artifact chain.

Do not turn a missing dependency into another tiny goal. When a subsystem has
several independent records or syscalls, plan and implement its full useful
contract together; split only where an actual safety, ABI, or artifact
dependency makes that necessary.
